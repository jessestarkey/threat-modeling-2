# Third-Party Icon Notices

This directory vendors icon assets from three different sources under three different terms. None of these icons are original work of this repository; each is used under the terms below. This file exists so those terms are visible to a reviewer auditing `icons/` directly, not only in scattered code comments in `threagile_dfd_to_html.py`.

Diagrams generated by this repository (`generate_report.py` / `threagile_dfd_to_html.py`) embed these files as-is via data URIs. No icon in `azure/` or `aws/` is ever recolored, cropped, rotated, or otherwise distorted, in either the source file or the rendered diagram — see the per-source terms below for why that specific constraint matters.

---

## `azure/*.svg` — Microsoft Azure Architecture Icons

Source: [Microsoft's official Azure Architecture Icons collection](https://learn.microsoft.com/en-us/azure/architecture/icons/), vendored unmodified.

Per Microsoft's published icon terms (as of this writing):

> Microsoft permits the use of these icons in architectural diagrams, training materials, or documentation. You can copy, distribute, and display the icons only for the permitted use unless granted explicit permission by Microsoft. Microsoft reserves all other rights.

Don'ts, also per that page: don't crop, flip, or rotate icons; don't distort or change icon shape in any way; don't use Microsoft product icons to represent your product or service. This repository's use (unmodified icons in architecture/data-flow diagrams) matches the permitted use case exactly, which is why `threagile_dfd_to_html.py`'s `render_icon()`/`render_icon_centered()` embed each file's untouched bytes rather than re-drawing or recoloring their paths.

Azure, Microsoft, and the names of individual Azure services depicted are trademarks of Microsoft Corporation.

`azure-app-gateway-print.png` and `azure-openai-print.png` are derived assets, not separately-vendored icons: plain, unmodified format conversions of `azure-app-gateway.svg`/`azure-openai.svg` (same 256×256 raster `_icon_data_uri_raster()` in `threagile_dfd_to_html.py` used to produce at report-render time via `cairosvg`, now pre-baked once instead — see that function's docstring) for the PDF-embedded diagram only, where WeasyPrint can't render either icon's gradient correctly (confirmed for `azure-openai.svg` the same way as `azure-app-gateway.svg` originally was: an isolated WeasyPrint render came back 0% non-white pixels, fully blank -- see `ICONS_NEEDING_PRINT_RASTER`'s own comment for why this wasn't just assumed from the shared `gradientTransform rotate(45)` pattern). No recoloring, cropping, or distortion — same constraint as the SVG each is derived from, just a different file format for the one rendering path that needs it. Regenerate the relevant one (rather than hand-edit it) if its source SVG is ever replaced.

### `human-web.svg`, `human-vdi.svg`, `machine-client.svg` — generic actor icons, not brand marks

These three are not product logos and not sourced from Simple Icons — they represent generic *actor types* (a human accessing via browser, a human accessing via virtual desktop/VDI, and a non-human/machine-to-machine API caller) for external-entity nodes in the diagrams, distinguishing "this is a person" from "this is a system" at a glance. Glyphs are [Heroicons](https://heroicons.com/) (`user`, `computer-desktop`, `server`, 24×24 solid variant), by Tailwind Labs, under the [MIT License](https://github.com/tailwindlabs/heroicons/blob/master/LICENSE) — fetched directly from Heroicons' own GitHub repository, not hand-transcribed. Recolored onto the same 64×64 background-square construction as the product glyphs above (background colors chosen for this repository, not carried from Heroicons, which ships monochrome `currentColor` glyphs with no fixed background): `human-web.svg` blue (`#2563EB`), `human-vdi.svg` violet (`#7C3AED`) — both in the same cool-color family to signal "human," distinguished by access path — and `machine-client.svg` orange (`#EA580C`), a deliberately different hue signaling "not human."

### `execution-environment.svg` — shared execution environment (`execution-environment` trust boundary type) boundary icon, not a brand mark

Not a product logo -- represents Threagile's own `execution-environment` trust boundary type ("a shared execution environment, e.g., same OS, same JVM"), used for a boundary wrapping technical assets that are co-resident processes on the same VM/host rather than separate network-reachable peers (e.g., an agent process and the VDI/AVD host it runs on). Cloud-provider-independent by design, the same reasoning `kubernetes.svg`/`k8s-namespace.svg` already apply -- this boundary type isn't Azure- or AWS-specific, so one icon covers it regardless of which cloud an app models. Glyph is Heroicons' `server-stack` (24×24 solid variant), by Tailwind Labs, under the [MIT License](https://github.com/tailwindlabs/heroicons/blob/master/LICENSE) -- fetched directly from Heroicons' own GitHub repository, not hand-transcribed. Recolored onto the same 64×64 background-square construction as the other Heroicons-sourced glyphs above, in a deliberately neutral slate grey (`#64748B`) rather than reusing any hue from the human/machine actor set above or the green family used for network trust boundaries -- this icon marks a boundary *type* badge, not an actor or a network segment, so it gets its own distinct, neutral color family.

### `k8s-namespace.svg` -- Kubernetes namespace boundary icon

Glyph is the "ns" (Namespace) resource icon from the official [Kubernetes community icon set](https://github.com/kubernetes/community/tree/main/icons) (`icons/svg/resources/unlabeled/ns.svg`), fetched directly from that repository, not hand-transcribed. That repository's `LICENSE` is Apache License 2.0 -- a permissive license covering the SVG artwork itself, permitting the recoloring/reconstruction done here (unlike the Azure/AWS sets above, which are vendored unmodified because their own terms require that). "Kubernetes" and its wheel logo remain trademarks of The Linux Foundation; this icon is the community-maintained "ns" resource glyph, not the Kubernetes project logo itself.

Recolored onto the same 64×64 background-square construction as the product glyphs above, using the glyph's own original color (`#326CE5`, Kubernetes' own brand blue -- not chosen by this repository) as the background, with the glyph itself in white. The one deviation from every other entry in this section: the source icon's own interior dashed-rectangle detail (visually distinguishing "namespace," a bounded/grouped concept, from other same-shaped Kubernetes resource icons in the same set, e.g. pod/svc/deploy) is kept in the background blue color rather than recolored to white, since a white-on-white dashed line would be invisible against the now-solid-white glyph -- confirmed by rendering both versions before choosing this one.

Selected as a cloud-provider-independent icon (`icon:k8s-namespace`) precisely because a Kubernetes namespace is the same concept whether the cluster is AKS or EKS -- one tag covers both, unlike the paired `icon:azure-*`/`icon:aws-*` tags above.

### `k8s-secret-csi.svg` -- Kubernetes Secrets Store CSI Driver icon

Same source and license as `k8s-namespace.svg` above: the official [Kubernetes community icon set](https://github.com/kubernetes/community/tree/main/icons) (`icons/svg/resources/unlabeled/secret.svg`), Apache License 2.0, fetched directly from that repository and recolored onto this repository's own 64×64 background-square construction -- the hexagonal Kubernetes "Secret" resource glyph in white on the same `#326CE5` Kubernetes brand blue background, with the glyph's own interior padlock detail kept in blue (inverted from the source's white-on-blue interior, the same "keep the inner distinguishing detail visible" adjustment `k8s-namespace.svg` already makes) rather than recolored to white, since a white padlock on a now-white hexagon would be invisible.

Selected (`icon:k8s-secret-csi`) as a cloud-provider-independent icon representing the AKS/EKS Secrets Store CSI Driver specifically, distinct from `icon:k8s-namespace`'s generic namespace-boundary meaning -- both can appear on the same diagram without conflict, one marking a boundary and one marking the CSI Driver technical asset itself.

## If adding a new icon

- **Official cloud-provider architecture icon** (new Azure/AWS service): download from the vendor's own official icon collection linked above, vendor unmodified, add to the corresponding table implicitly by adding the file — no recoloring, cropping, or distortion, ever.
- **Self-hosted open-source or commercial software**: check [simpleicons.org](https://simpleicons.org/) first for a CC0 glyph; if present, follow the existing `opensource/*.svg` construction (64×64 square, brand color background, white glyph, `translate(14,14) scale(1.5)`) and add a row to the table above. If no Simple Icons glyph exists, vendor the product's own official logo/favicon unmodified (as done for `open-webui.svg`) rather than inventing an icon.
- Either way, add the corresponding entry to `03-tags-lib.yml`'s "DIAGRAM ICON TAGS" section and `threagile_dfd_to_html.py`'s `ICON_FILES` dict — see `CLAUDE.md`'s "Giving an asset/boundary a diagram icon" bullet.
